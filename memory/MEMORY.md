Pi skill loading is two-layered. Eager (every request, always): pi scans `~/.agents/skills/`, `settings.skills`, and packages, injecting `name + description + location` into the system prompt via `formatSkillsForPrompt` — ~2,886 tokens across 36 model-visible skills as of 2026-10-09. Lazy (on demand only): the skill body loads only when the model invokes it. Name collisions are *free* for tokens because the skipped duplicate never enters the prompt — the winner loads whether or not the loser exists. Token savings come only from reducing model-visible winners (their listing chars), not from resolving collisions. <!-- created=2026-10-09, last=2026-10-09 -->
