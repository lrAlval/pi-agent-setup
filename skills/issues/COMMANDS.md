# Issues — Command Reference

Exact `gh` recipes for the `issues` skill. `<N>` = issue number, `<X>` = PR number.
All dates UTC, ISO-8601 (`date -u +%Y-%m-%dT%H:%MZ`). Audit comments always start with the disclaimer line.

## 0. Context

```bash
OWNER_REPO=$(gh repo view --json nameWithOwner --jq .nameWithOwner)
ME=$(gh api user --jq .login)
```

## 1. Ensure labels (idempotent)

```bash
gh label create "status/backlog"     --color "B0365A" --description "New, not yet specified" 2>/dev/null || true
gh label create "status/ready"       --color "0E8A16" --description "Fully specified, claimable" 2>/dev/null || true
gh label create "status/in-progress" --color "1D76DB" --description "Claimed, being worked" 2>/dev/null || true
gh label create "status/in-review"   --color "5319E7" --description "Open PR linked" 2>/dev/null || true
gh label create "status/done"        --color "006B75" --description "Confirmed complete or PR merged" 2>/dev/null || true
gh label create "priority/P0" --color "B60205" --description "Critical" 2>/dev/null || true
gh label create "priority/P1" --color "D93F0B" --description "High" 2>/dev/null || true
gh label create "priority/P2" --color "FBCA04" --description "Normal" 2>/dev/null || true
gh label create "priority/P3" --color "0E8A16" --description "Low" 2>/dev/null || true
```

## 2. Read one issue (labels, body, comments)

```bash
gh issue view <N> --json number,title,body,labels,assignees,state,createdAt,comments
# labels only:
gh issue view <N> --json labels --jq '.labels[].name'
```

## 3. Hygiene check (flag 0 or 2+ status/priority labels)

```bash
# open issues with all labels; filter locally with jq:
gh issue list --state open --limit 200 --json number,title,labels \
  --jq '.[] | {number, title, status: [.labels[].name | select(startswith("status/"))], prio: [.labels[].name | select(startswith("priority/"))]}
        | select((.status|length)!=1 or (.prio|length)!=1)'
```

## 4. next — ranked ready list

```bash
gh issue list --state open --label "status/ready" --limit 100 \
  --json number,title,createdAt,labels,body \
  --jq 'sort_by(.createdAt) | sort_by(([.labels[].name | select(startswith("priority/"))] | first // "priority/P2") | ltrimstr("priority/P") | tonumber) | .[]'
# then apply Blocked-by deferral locally: body match (?i)(blocked by|depends on)\s+#(\d+),
# blocker Done? => gh issue view <M> --json labels --jq 'any(.labels[].name; .=="status/done")'
```

## 5. claim

```bash
ASSIGNEE="${1:-$ME}"
CUR=$(gh issue view <N> --json labels --jq '[.labels[].name | select(startswith("status/"))]')
# refuse if CUR contains status/in-progress or status/done
gh issue edit <N> --add-assignee "$ASSIGNEE"
gh issue edit <N> --remove-label "$(echo "$CUR" | jq -r '.[]')" --add-label "status/in-progress"
gh issue comment <N> --body "> *This was generated by AI during triage.*

status: <Old> -> In Progress (claimed by @$ASSIGNEE, <date>)"
```

## 6. move (manual override, any → any)

```bash
gh issue edit <N> --remove-label "<old-status>" --add-label "status/<new>"
# optional: gh issue edit <N> --remove-label "<old-prio>" --add-label "priority/<P>"
gh issue comment <N> --body "> *This was generated by AI during triage.*

status: <Old> -> <New> (<reason>, <date>)"
```

## 7. scan — PR linkage + feedback

Linked PRs via timeline cross-references:

```bash
gh api "repos/$OWNER_REPO/issues/<N>/timeline" --paginate \
  --jq '.[] | select(.event=="cross-referenced" and (.source.issue.pull_request!=null or .source.issue.html_url|contains("/pull/"))) | .source.issue.number'
```

Keyword search over open PRs:

```bash
gh pr list --state open --limit 100 --json number,body \
  --jq --argjson n <N> '.[] | select(.body // "" | test("(?i)(closes|fixes|resolves)\\s+#\($n)\\b")) | .number'
```

Merge state + comments (cursor = last `status:` comment on the issue):

```bash
gh pr view <X> --json state,mergedAt,author,comments,reviews
LAST=$(gh issue view <N> --json comments --jq '[.comments[] | select(.body // "" | startswith("status:")) | .createdAt] | max // "1970-01-01T00:00Z"')
# new non-author comment/review since $LAST on PR <X> => back to In Progress
# PR merged (state==MERGED / mergedAt!=null) => Done
```

Transitions use the same `gh issue edit` + `gh issue comment` pattern as §5/§6 with reasons
`PR #X opened`, `new feedback from @user on PR #X`, `PR #X merged`.

## 8. bulk (dry-run default, `--yes` applies)

Selection:

```bash
# explicit:
gh issue view <N> --json number,title,labels,assignees  # per N in list
# or filter (gh ANDs multiple --label flags):
gh issue list --state open --label "status/in-review" --label "priority/P1" --limit 200 \
  --json number,title,labels,assignees
# --assignee / extra --label narrow further; jq-filter locally for unions
```

Preview table first (issue | current → proposed | eligible?). With `--yes`, loop eligible issues
through §5/§6 recipes, one audit comment each. Print skipped list with reasons.

## 9. fix-labels (one-shot hygiene repair)

```bash
# per flagged issue, after dev confirms target labels:
gh issue edit <N> --remove-label "<wrong-status>" --add-label "status/<correct>"
gh issue edit <N> --remove-label "<wrong-prio>" --add-label "priority/<P>"  # default P2 only if accepted
gh issue comment <N> --body "> *This was generated by AI during triage.*

labels fixed: status=<s> priority=<P> (<date>)"
# re-run §3 to prove clean
```
